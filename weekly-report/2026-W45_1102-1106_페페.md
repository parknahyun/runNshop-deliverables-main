## 2. 상세 작업 내역

### 2.1 (10/29 목 08:37) 외부 정책서 초안 반영 및 정책서 문서 분리 개편

- 외부 제공 "주문.결제 정책서(임시)" 초안(926줄)을 산출물로 편입하고, 기존 통합 `order.md`를 주문(`order.md`)·배송(`order-shipping.md`)·클레임(`order-claim.md`)·결제·환불(`payment.md`)·알림(`notification.md`)·정산(`settlement.md`) 6개 문서로 분리
- `catalog-display.md`(159줄) 신설 — 화면별 할인가 노출 정책을 Catalog 소유로 정식 확정

### 2.2 (11/03 화 08:08) 주문·결제 확정 결정 대량 반영 — 산출물 일괄 현행화

- 가장 큰 단일 커밋(134개 파일, +7,563/-4,258줄) — S0~S3 전 단계 산출물에 그 사이 확정된 다수의 정책 결정(반품 접수기한 10일, 자동구매확정 11일, 쿠폰 할인 4단계 적용순서, 이용 제한 정책 수용, 개인정보 마스킹 정책 수용 등)을 한 번에 반영
- 화면정의서(DN) mobile 통합 파일(2,016줄)을 11개 화면별 파일로 분해, admin/partner 클레임·주문 상세를 탭 단위 파일로 분리
- DO-ADR을 Catalog/Order-Payment로 분리하던 작업 마무리

### 2.3 (11/03 화 10:06) 주문·결제 후속 결정 반영 및 산출물·프로그램 목록 현행화

### 2.5 (11/03 화 13:07~15:21) Order·Payment 상세설계 산출물 상세검토 및 후속 반영 (Kiro AI 협업)

- S2-구조설계 7종(DBA·DC·DD·DF·DG·DH·DI)·S3-상세설계 7종(DJ·DK·DL·DM·DO-ADR·DP·DQ)을 Order·Payment 양 도메인 기준으로 교차검토
- 발견·수정한 불일치 3건:
  1. 장바구니 최대 담기 수량 — 정책서(100개) vs 하위 산출물 6종(50개) 불일치 → 50개로 통일
  2. 포인트 소유 도메인 미확정(Member 추정으로만 남아있던 Human Review 항목) → **Member로 확정**, `order.md` 1.3.1 신설
  3. DQ 프로그램목록의 컨슈머 표(CSM-001/002)가 DH v7에서 폐기된 구 상태명(`PAYMENT_PENDING`)을 그대로 사용 → 현행 상태명으로 정정
- 이벤트플로우(DI)를 비동기 재설계(ADR-007 비동기 접수, ADR-008 결제확인중, ADR-009 취소우선·LATE_DEPOSIT)에 맞춰 갱신 — 이벤트 카탈로그·흐름도·동기/비동기 판단표 전면 수정
- 환불완료 통지용 **`PAYMENT_REFUNDED` 이벤트 신규 설계** — DD(REQ-PAY-032)·DG(발행 단계 3곳)·DI(스키마)·DM(시퀀스)·DP(`PaymentEventPublisher`·`RefundService` 배선)까지 5개 문서 일관 반영
- **타도메인 지원 필요 기능 목록** 신규 작성(`review-alignment/설계/주문결제_타도메인_지원필요기능_목록.md`) — Member·Catalog·Promotion·Vendor·Settlement·Notification·Audit 7개 도메인별 연동 기능과 구체적 제안 API(Port 시그니처), 협의내용 정리. 후속 피드백으로 상품 즉시할인의 Catalog/Promotion 소유권 분리, 할인 차수·시점·우선순위, 사은품 지급, 적립 프로모션 4건 추가
- Bolt1 검토 문서 2종 중복 정리 — `Bolt1_산출물목록_및_내용검토.md`를 `Bolt1_프로그램목록_정리.md`로 통합 후 삭제
- PR #9(10/29~11/03 반영분, 7 커밋)·PR #10(상세검토·정리분, 3 커밋) 생성 후 `main`에 머지

## 3. 확정된 주요 결정사항

| 결정 | 내용 |
|------|------|
| 포인트 소유 도메인 확정 | **Member 도메인**으로 확정(`DBA-도메인정책서/order.md` 1.3.1). Human Review 항목에 오래 남아있던 미정 사항 해소 |
| 장바구니 최대 담기 수량 통일 | 50개로 통일(정책서의 100개는 하위 6개 산출물과 불일치하던 값으로, 외부 초안 반영 시 생긴 오차였음) |
| `PAYMENT_REFUNDED` 이벤트 신설 | Payment가 수행하는 환불 4경로(주문취소 자동·어드민 클레임환불·LATE_DEPOSIT 자동환불·CS 수동) 공통으로 발행, 수신은 Notification만(Settlement는 매출 미인식 금액이라 제외) |
| 비동기 접수 모델(ADR-007~009) 최종 반영 | 이벤트플로우(DI)가 그동안 "동기 재고선점+동기 결제요청" 전제로 멈춰 있던 것을 현행 비동기 모델로 갱신 완료 |
| Settlement API 설계는 추후 정의 | Settlement 도메인 자체가 4차 파트 미착수라, 지금 Port 시그니처를 제안해도 검증 불가 — "무엇을 넘겨야 하는가"까지만 정리하고 실제 API 스펙은 Settlement 착수 시점에 재협의 |
| DQ-프로그램목록 Bolt1 세부 문서(`order-bolt1.md`) 정식 편입 | 기능 단위(B1-*) 90건 상세를 도메인 공용 산출물로 확정 |
