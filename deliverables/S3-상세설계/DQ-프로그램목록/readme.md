## 도메인별 파일

프로그램 소유는 **API는 URL 소유 도메인, 컨슈머(CSM)는 수신(구현) 도메인** 기준으로 나눈다.
화면(SCR)·배치(BAT)는 호출/실행하는 도메인 로직 기준으로 나눈다.

| 구분 | 파일 | 화면(SCR) | API | 컨슈머(CSM) | 배치(BAT) |
|---|---|---|---|---|---|
| Order 도메인 | [order.md](order.md) | 37 | 52 (API-051~058 추가, API-053~055는 내부 API) | 4 (CSM-001, 002, 005, 006) | 10 (BAT-005~007, 011~013 추가) |
| Payment 도메인 | [payment.md](payment.md) | 1 (SCR-M-012) | 8 (API-019~021, 044~046, 059, 060) | 2 (CSM-003, 004) | 3 (BAT-008~010) |
| Catalog 도메인 | [catalog.md](catalog.md) | 28 (SCR-A-C*/SCR-P-C*/SCR-M-C*) | 36 (API-CAT-001~032, 하위번호 포함) | 6 (CSM-CAT-001~006) | 2 (BAT-CAT-001~002) |
| Bolt1 기능 단위 상세 | [order-bolt1.md](order-bolt1.md) | Bolt1(주문 신청) 기능 90건 — 화면(모바일·어드민·판매자)·API·Consumer·Batch 구분 | | | |

> 컨슈머는 "발행 도메인"이 아니라 "수신 도메인" 기준으로 나눈다 — 컨슈머 코드는 이벤트를
> 수신하는 쪽 도메인에 구현되기 때문이다(이벤트플로우(DI)의 파일 분리 기준인 "발행 도메인"과
> 반대 축). 예: `CSM-001`(PAYMENT_APPROVED 수신)은 Payment가 발행하지만 Order가 구현하므로
> order.md에 있다.
