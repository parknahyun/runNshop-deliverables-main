> **구현 현황 (2026-10-29)**: 이 화면의 데이터 소스 API(`/api/admin/v1/claims*`)는 **BE에 없고 미구현**이며, 현행 FE(`ClaimPage.tsx`)는 인메모리 `MOCK_CLAIMS`를 거르는 **Mock 화면**이다. 상세는 MDI 탭이 아니라 **모달**(`DETAIL_MODE='modal'`, 코드상 'tab' 전환 가능)로 열린다. ### 화면 구성

| 영역 | 데이터 소스 (API) | 표시 내용 |
|---|---|---|
| 타이틀 | — | "클레임 관리" |
| FilterBar | — (FE 상태) | 키워드(클레임번호·주문번호·고객명), 유형 Select(취소/반품/교환), 상태 Select, 귀책 Select(고객/판매자 — 2종), 기간(from~to), 조회 버튼 |
| SummaryBar | GET /api/admin/v1/claims → 집계 (**API 미구현 — 현행은 FE Mock, 클라이언트 집계**) | 전체·접수·처리중·완료·반려·**⚠미처리임박(접수 후 24시간 미처리, RECEIVED 상태 방치 건)** 건수 카드 (REQ-ORD-068) — **⚠미처리임박 카드 미구현** (현행 5카드) |
| Toolbar | — | 엑셀 다운로드 버튼 |
| ClaimTable (DataGrid) | GET /api/admin/v1/claims (**API 미구현 — 현행 FE Mock**) | 클레임번호, 원주문번호, 유형, 상태(뱃지 — **접수(RECEIVED) 후 24시간 초과 시 ⚠ 강조 아이콘 표시 — 미구현**), 귀책(뱃지), 신청경로, 환불금액, 신청일시, 처리완료일시 |
| Pagination | — (FE 상태) | 페이지 이동, 페이지 사이즈 변경 |

> **귀책 값 (2026-10-29 확정)**: 귀책은 `CUSTOMER`(고객 귀책)·`VENDOR`(판매자 귀책) **2종**이다(정책서 order-claim.md 7.4.4, DH v6, DF `responsibility`). `PLATFORM`(플랫폼 귀책)과 `PENDING`(판정 전)은 구버전으로 폐기한다. 판정 전에는 `responsibility`가 비어 있고 화면은 "판정 전"으로 표시하며, 고객 자진신고는 `submitted_responsibility`로 보여준다. 현행 FE(`claim/mockData.ts`의 `BlameType`)는 4종이 남아 있어 **구현 갭**이다(코드 미수정). 표기는 "고객 귀책/판매자 귀책"으로 통일한다.

#### 표시 상태 ↔ DH 클레임 상태 매핑 (제안)

화면의 4종 표시 상태는 DH 클레임 상태 11종([DH order](../../../../S2-구조설계/DH-상태머신/order.md))을 묶은 파생 값이다. "처리중"은 DH에 없는 상태이며, API-050(처리 시작)을 호출해도 `claim.status`는 `RECEIVED`로 유지된다(DL §19).

| 표시 상태 | DH 상태 |
|---|---|
| 접수 | RECEIVED |
| 처리중 | PAYMENT_PENDING, INSPECTING, PICKED_UP, PICKUP_REJECTED, RETURN_PAYMENT_PENDING |
| 완료 | REFUNDED, DISPOSED, COMPLETED |
| 반려 | REJECTED |

> [확인 필요: PAYMENT_EXPIRED(결제 만료 자동 취소)를 어느 표시 상태로 둘지, 정책 order-claim 7.7 상태명과의 대응 확정]
