SummaryBar는 서버 집계가 아니라 `summary=null`(`OrderService.kt:226-230`)이며 FE가 현재 페이지로 계산하고(`OrderListPage.tsx:97-100`) 접수 카드는 없다. 주문확인·배송지연 표시는 설계에 없고(정책 6.4.7·6.13.1은 확정) 구현에도 없다.

### 화면 구성

| 영역 | 데이터 소스 (API) | 표시 내용 |
|---|---|---|
| 타이틀 | — | "주문 목록" |
| FilterBar | — (FE 상태) | 상태 Select, 기간(from~to), 키워드(주문번호·상품명·고객명), 조회 버튼 |
| SummaryBar | GET /api/partner/v1/orders → 집계 (설계) · 현 구현: FE가 현재 페이지 데이터로 계산, 서버 `summary=null` | 전체·접수(프로토타입 미구현)·결제완료·준비중·배송중·배송완료 건수 카드 |
| Toolbar | — | 엑셀 다운로드, 일괄 출고 처리 버튼 |
| OrderTable (DataGrid) | GET /api/partner/v1/orders | 주문번호(orderNo, vendor 주문번호 — 필드명 확인 필요, 위 "주문번호 바인딩" 참조), 상품명, 고객명, 수량, 금액, 상태(뱃지), 주문일자 |
| Pagination | — (FE 상태) | 페이지 이동, 페이지 사이즈 변경 |
