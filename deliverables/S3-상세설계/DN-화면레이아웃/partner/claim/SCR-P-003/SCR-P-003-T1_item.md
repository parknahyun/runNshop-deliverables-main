### 화면 구성

> [admin 클레임 상세](../../../admin/claim/SCR-A-004/SCR-A-004_detail.md) 구성을 참조하되 판매자 권한 차이가 있다(아래 권한 차이 표). 탭 데이터는 모두 단일 상세 API [[DL-인터페이스명세/order|API-057]]의 응답 섹션(`items[]`·`shipments[]`·`history[]`)에서 가져온다(DL 탭별 Sub-API 정책, 2026-10-29 신설·미구현).

| 탭 | 데이터 소스 (API) | 표시 내용 |
|---|---|---|
| 클레임상품 (ClaimItemTab) | GET /api/partner/v1/claims/{claimId} (API-057) → `items[]` | 원주문번호(orderNo, vendor 주문번호), 접수일, 사유·상세사유, 귀책, 상품 테이블(상품명*/옵션*/수량/상품주문금액/상태), **첨부사진("고객 첨부" 라벨로 표시, 조회만 — 접수 시 고객 업로드)**. 판매자 액션: [수거 완료 확인], [품질점검 합격/불합격] (메모 입력 + 교환 건은 택(TAG) 유지 여부 체크 필수 + **불합격 선택 시 증빙 사진 1장 이상 첨부 필수(REQ-ORD-072) — DL `INSPECT_PHOTO_REQUIRED`는 `claimType=EXCHANGE`일 때만 적용**. [확인 필요: 반품(RETURN) 불합격에도 사진이 필수인지]), [재배송 처리](PICKUP 진입 시 즉시 가능 — 교환상품 선출고 운송장 등록, 품질점검 이전에 완료) |

> \* 상품명·옵션명은 주문(ord_order_item)의 스냅샷 속성

> 첨부 사진 규칙(partner): "고객 첨부" 사진은 접수 시 고객이 올린 것으로 조회만 한다. 품질점검 불합격 증빙 사진은 판매자가 업로드하는 사진이며, 업로드 후 partner 화면에서 다시 보이는 방식(썸네일·삭제 가능 여부)은 [확인 필요: partner 노출 규칙]이다.

### 버튼별 활성 조건·호출 API

| 버튼 | 호출 API | 활성 조건 (claim.status / shipment.status) |
|---|---|---|
| [수거 완료 확인] (입고 확인 → 품질점검 시작) | API-038 `pickup-confirm` | shipment(PICKUP).status=IN_TRANSIT, 호출 시 claim.status → INSPECTING. 고객 귀책은 클레임 배송비 결제완료 후 [확인 필요: claim.status 조합] |
| (수거 운송장 등록) | API-037 `shipping/{claimId}/pickup` | shipment(PICKUP).status=PENDING. 고객 귀책은 배송비 결제완료 후 (배송정보 탭 / 배송 관리 화면에서 입력) |
| [품질점검 합격] | API-039 `inspect-pass` | claim.status=INSPECTING → PICKED_UP. 교환은 택(TAG) 유지 필수 |
| [품질점검 불합격] | API-040 `inspect-reject` | claim.status=INSPECTING → PICKUP_REJECTED. 사유 필수, 교환은 증빙 사진 1장 이상 |
| [재배송 처리] | API-043 `exchange-ship` | EXCHANGE 전용. PICKUP 진입 시 shipment(EXCHANGE_OUT).status=PENDING이면 즉시 활성(품질점검과 무관) |
| (반송 운송장 등록) | API-041 `return-ship` | claim.status=RETURN_PAYMENT_PENDING, 반송배송비 결제완료 후 shipment(RETURN).status=PENDING |

> 위 조합은 DQ API-037~043 비고와 DH 전이 기준이며, 와이어프레임의 4개 버튼([수거 완료 확인]·[품질점검 합격]·[품질점검 불합격]·[재배송 처리])과 운송장 등록 API의 화면 대응은 TBD(확정 근거 부족).
