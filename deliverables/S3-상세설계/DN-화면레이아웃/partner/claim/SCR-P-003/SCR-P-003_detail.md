## 13-1. partner — 클레임 상세 (ClaimDetail MDI 탭)

> [admin 클레임 상세](../../../admin/claim/SCR-A-004/SCR-A-004_detail.md)(§12-1)를 참조. 판매자는 접수·처리 판정 불가, 수거확인·품질점검·재배송 수행.

### 화면 구성 (ClaimDetail — MDI 탭)

> [admin 클레임 상세](../../../admin/claim/SCR-A-004/SCR-A-004_detail.md) 구성을 참조하되 판매자 권한 차이가 있다(아래 권한 차이 표). 탭 데이터는 모두 단일 상세 API [[DL-인터페이스명세/order|API-057]]의 응답 섹션(`items[]`·`shipments[]`·`history[]`)에서 가져온다(DL 탭별 Sub-API 정책, 2026-10-29 신설·미구현).

| 탭 | 탭 문서 | 데이터 소스 (API) | 요약 |
|---|---|---|---|
| 클레임상품 (ClaimItemTab) | [SCR-P-003-T1](SCR-P-003-T1_item.md) | GET /api/partner/v1/claims/{claimId} (API-057) → `items[]` | 판매자 액션 포함 — 수거 완료 확인·품질점검·재배송 |
| 배송정보 (ShippingTab) | [SCR-P-003-T2](SCR-P-003-T2_shipping.md) | GET /api/partner/v1/claims/{claimId} (API-057) → `shipments[]` | 클레임 배송비·수거·재배송·반송 정보 |
| 변경이력 (LogTab) | [SCR-P-003-T3](SCR-P-003-T3_log.md) | GET /api/partner/v1/claims/{claimId} (API-057) → `history[]` | 타임라인 |

> 탭별 표시 내용·버튼별 활성 조건·첨부 사진 규칙은 각 탭 문서를 참조한다.

### admin vs partner 클레임상세 권한 차이

| 기능 | [admin](../../../admin/claim/SCR-A-004/SCR-A-004_detail.md) (§12-1) | partner (§13-1) |
|---|---|---|
| 클레임 접수·처리시작 | ✅ | ❌ |
| 처리 완료 (환불 진행) | ✅ | ❌ |
| 반려 | ✅ | ❌ |
| 환불정보 조회·계좌 입력 | ✅ | ❌ (환불 탭 없음) |
| 수거 완료 확인 | ✅ | ✅ |
| 품질점검 합격/불합격 | ✅ | ✅ |
| 재배송 처리 (운송장 등록) | ✅ | ✅ |
| 변경이력 조회 | ✅ | ✅ |

> [확인 필요: admin 클레임 상세에는 수거 완료 확인·품질점검 합격/불합격·재배송 버튼이 없고, 귀책 판정·폐기·반송결제요청·FAILED 재발송 행이 위 표에 빠져 있다. 정책 7.7.3 "운영자는 전 단계 처리 가능"으로 권한상 가능할 수 있으나 화면·API 근거가 없어 ✅ 표기의 정정 여부를 admin 문서·DQ와 함께 결정]

### 화면 전환

> SCR-P-002 주문상세 또는 SCR-P-005 클레임 현황에서 MDI 탭으로 진입한다. 이 화면에서 다른 화면으로의 이동은 없고 탭·모달 전환만 있다.

| 트리거 | 동작 |
|---|---|
| 내부 탭 전환 (클레임상품/배송정보/변경이력) | SCR-P-003-T1~T3 (같은 MDI 탭 내 전환, 화면 이동 아님) |

### 유효성 검증

> 해당 없음 (컨테이너). 탭별 검증은 [SCR-P-003-T1](SCR-P-003-T1_item.md)·[T2](SCR-P-003-T2_shipping.md)를 참조한다.
