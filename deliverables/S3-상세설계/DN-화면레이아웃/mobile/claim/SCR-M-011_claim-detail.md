> **구현 현황 (2026-10-29)**: 클레임 상세는 `ClaimController.kt`의 Mock GET 조회(`mobile__GET_my_claims_{claim_id}.json`)만 구현돼 있고 Service/DB는 연동되지 않았다. FE(`app/my/claims/[claimId]/page.tsx`)에는 사유·수거·환불·타임라인만 있으며, 배송비 결제 섹션·결제 팝업·`shippingPayments[]`(Mock JSON에 키 없음)·[취소] 버튼(API-049, DQ상 "추가예정")은 설계안이며 프로토타입 미구현이다.

### 화면 구성

| 영역 | 데이터 소스 (API) | 표시 내용 |
|---|---|---|
| Header + 뒤로가기 | — | "← {유형} 상세" + 상태뱃지 + **[취소] 버튼**(상태=RECEIVED 또는 PAYMENT_PENDING일 때만 노출 — 고객 자진취소, 설계안·프로토타입 미구현) |
| 상품 정보 | GET /api/mobile/v1/my/claims/{claimId} (API-017) | 상품이미지, 상품명, 옵션, 수량, 금액, 주문번호(platformOrderNo), 클레임번호, 접수일시 |
| 클레임 사유 | 동일 API → `reason`, `detailReason` | 사유, 상세 설명, 귀책(고객/판매자 — 2종), 반품 배송비 |
| 배송비 결제 | 동일 API → `shippingPayments[]` (**프로토타입 미구현** — Mock에 키 없음) | 수거 배송비(결제 상태/일시), 반송 배송비(품질점검 불합격 시 노출). [배송비 결제하기] 버튼 → 레이어 팝업(쿠폰 적용 + 결제수단 선택) → PG SDK 결제 → 완료 후 클레임 상세 화면에서 결제완료 상태 반영 (팝업 닫힘, 상태 갱신). POST /api/mobile/v1/my/claims/{claimId}/shipping-payment (API-018) |
| 수거 정보 | 동일 API → `pickup` | 택배사, 운송장번호, 수거 상태(진행중 표시), 요청일시 |
| 환불 정보 | 동일 API → `refund` | 환불 수단(마스킹 카드번호), 환불 상태, 예상 일정, 환불 금액 |
| 처리 타임라인 (ClaimStatusTimeline) | 동일 API → `timeline[]` | 시간순 이벤트 목록 (접수→확인→수거요청→수거진행 등), 최신 이벤트 강조 |
| BottomNav | — | 홈/기획전/검색/MY |

> **환불 산식 (2026-10-29 확정)**: 수거·반송 배송비는 고객이 별도 결제하며 환불금액에서 차감하지 않는다. 예: 상품주문금액 169,000원이면 환불금액도 169,000원이다.

| [취소] 클릭 | 확인 팝업 (화면 전환 아님, 프로토타입 미구현) |

|---|---|
