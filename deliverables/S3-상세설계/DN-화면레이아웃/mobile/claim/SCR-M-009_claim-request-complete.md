## 8-3. mobile — 반품/교환 신청 완료 (ClaimRequestCompletePage)

> **진입**: [SCR-M-008_claim-request.md](SCR-M-008_claim-request.md)에서 [신청하기] 성공 후 이동.
> 고객 귀책으로 배송비가 발생하는 경우 이 화면에서 바로 배송비 결제로 연결된다.

### 메타블록

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-M-009 |
| 앱 | mobile |
| 접근 권한 | 로그인 회원 |
| 관련 세부UC | [[DK-세부유스케이스/order|UC-19]] |
| 호출 API | 없음 (클레임 신청 응답 표시만, [[DL-인터페이스명세/order|API-013]] 응답 재사용 — 설계안, 프로토타입 미구현) |

> **구현 현황 (2026-10-29)**: 이 화면(SCR-M-009)은 설계안이며 프로토타입 미구현이다 — FE에 라우트가 없고 선행 API(`POST /api/mobile/v1/my/orders/{orderId}/claims`, API-013)도 BE에 없다. 아래 접수 요약·배송비 결제 안내는 구현 전 설계 기준이다.

### 화면 구성

| 영역 | 데이터 소스 (API) | 표시 내용 |
|---|---|---|
| 완료 아이콘 + 메시지 | — | ✅ + "{유형} 신청이 완료되었습니다" |
| 접수 요약 | POST /api/mobile/v1/my/orders/{orderId}/claims (API-013) → 응답 | 클레임번호, 유형, 신청상품명, 접수일시 |
| 배송비 결제 안내 | 동일 응답 → `shippingFeeRequired`, `shippingFeeAmount` | 고객 귀책 시 노출: 수거 배송비 금액, 결제 기한(24시간), 미결제 시 자동 취소 안내 |
| [배송비 결제하기] 버튼 | — | 클릭 시 배송비 결제 레이어 팝업 ([SCR-M-011_claim-detail.md](SCR-M-011_claim-detail.md)의 배송비 결제 팝업과 동일, 설계안·프로토타입 미구현) |
| CTA 버튼 | — | "클레임 상세 보기" → /my/claims/{claimId}, "쇼핑 계속하기" → / |
| BottomNav | — | 홈/기획전/검색/MY |

### 화면 전환

| 트리거 | 이동 화면 (SCR-ID) |
|---|---|
| [배송비 결제하기] 클릭 | 레이어 팝업 (화면 전환 아님, [SCR-M-011_claim-detail.md](SCR-M-011_claim-detail.md)와 동일) |
| [클레임 상세 보기] 클릭 | SCR-M-011 (클레임 상세) |
| [쇼핑 계속하기] 클릭 | 홈 |

### 유효성 검증

> 해당 없음 (결과 표시 화면)

### 상태별 UI

| 상태 | 화면 표현 |
|---|---|
| 판매자 귀책 (배송비 미발생) | 배송비 결제 영역 비노출, "수거가 자동으로 진행됩니다" 안내 |
| 고객 귀책 (배송비 발생) | 배송비 결제 영역 노출 + [배송비 결제하기] 버튼 |
| 기타 (CS 확인 필요) | "CS 확인 후 안내드리겠습니다" 메시지, 배송비 영역 비노출 |
| 배송비 결제 완료 | "배송비 결제 완료 (6,000원)" 표시 → 수거 진행 안내 |

### 귀책 판정 기준 (사유 → 귀책 매핑)

| 사유 | 귀책 | 배송비 |
|---|---|---|
| 단순 변심 | 고객 | 발생 |
| 사이즈가 맞지 않음 | 고객 | 발생 |
| 상품 불량/파손 | 판매자 | 미발생 |
| 오배송 | 판매자 | 미발생 |
| 기타 | CS 확인 후 결정 | 보류 (CS 판정 후 결제 요청) |
