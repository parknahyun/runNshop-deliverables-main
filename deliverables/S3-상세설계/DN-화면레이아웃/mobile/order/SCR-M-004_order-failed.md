## 4. mobile — 주문 접수 실패 (OrderFailedPage)

> **진입 조건**: 주문 데이터가 생성되지 못한 경우 즉시 노출 (유효성 검증 실패, 시스템 오류 등).
> 주문 데이터가 생성된 이후 재고 확보 실패·PG 결제 실패는 이 화면이 아니라 메일/문자([notification.md](notification.md))로 안내(알림 발송은 현재 미구현).

### 상태별 UI (접수 실패 유형)

> **구현 현황 (2026-10-29)**: 아래 3종 유형(VALIDATION_ERROR·SYSTEM_ERROR·SESSION_EXPIRED) 분기는 설계안이며 프로토타입 미구현이다. 현재 FE는 `ApiError.message` 또는 고정 문구만 표시하고 유형 분기가 없다. 실제 접수 실패 사유는 [DL order.md §6](../../../DL-인터페이스명세/order.md)의 에러코드 기준이며 아래 "DL 에러코드 기준" 표와 같다.

**설계안 (유형 분기, 프로토타입 미구현)**

| 실패 유형 | 메시지 | 안내 문구 |
|---|---|---|
| VALIDATION_ERROR | "필수 정보가 누락되었습니다" | "주문서를 확인 후 다시 시도해 주세요" |
| SYSTEM_ERROR | "일시적인 오류로 주문을 접수할 수 없습니다" | "잠시 후 다시 시도해 주세요" |
| SESSION_EXPIRED | "세션이 만료되었습니다" | "다시 로그인 후 시도해 주세요" |

**현행 (DL §6 에러코드 기준)**

| HTTP | code | 사유 |
|---|---|---|
| 400 | CART_ITEMS_REQUIRED | 주문할 상품이 없음 |
| 400 | ADDRESS_REQUIRED | 배송지 미선택 |
| 400 | TERMS_NOT_AGREED | 필수 약관 미동의 |
| 400 | PAYMENT_METHOD_NOT_READY | 카드 결제는 작업중(현재 가상계좌만 진행) |
| 400 | REFUND_ACCOUNT_REQUIRED | 가상계좌 선택 시 환불계좌(은행·계좌번호·예금주) 미입력 (설계안 — 환불계좌 입력 UI 프로토타입 미구현) |
| 422 | REFUND_ACCOUNT_INVALID | 환불계좌 검증 실패(예금주가 주문자 본인과 다름·실명 확인 실패) (설계안) |
| 400 | INVALID_PAYMENT_METHOD / INVALID_ITEM_PRICE | 지원하지 않는 결제수단 / 수량·가격·포인트 값 오류 |
| 422 | COUPON_NOT_APPLICABLE | 적용할 수 없는 쿠폰 |
| 422 | POINT_EXCEED | 사용 가능 포인트 초과 |
| 404/403/422 | ORDER_SHEET_NOT_FOUND / ORDER_SHEET_FORBIDDEN / ORDER_SHEET_ALREADY_PROCESSED | 주문서 없음 / 본인 주문서 아님 / 이미 결제 진행됨 |

> **주문 접수 실패 vs 재고/결제 실패 안내 차이**
>
> | 구분 | 시점 | 주문 데이터 | 안내 방식 | 안내 내용 |
> |---|---|---|---|---|
> | 주문 접수 실패 (이 문서) | 즉시 (주문 생성 전) | 생성 안 됨 | 화면에서 직접 안내 | "접수에 실패했습니다" + 다시 시도 유도 |
> | 재고 확보 실패 | 백그라운드 (주문 생성 후) | 생성됨 → `STOCK_FAILED`(재고부족) 확정 | 메일/문자로 안내 ([notification.md](notification.md), 발송 미구현 — 주문 상세 상태로 확인) | "재고 부족으로 주문이 취소되었습니다" + "결제가 진행되지 않았으며 청구되지 않습니다"(재고 확보가 결제보다 먼저라 환불 없음) |
> | PG 결제 실패 | 백그라운드 (주문 생성 후) | 생성됨 → 실패 전환 | 메일/문자로 안내 ([notification.md](notification.md)) | "결제가 승인되지 않았습니다" + 재주문 안내 |
