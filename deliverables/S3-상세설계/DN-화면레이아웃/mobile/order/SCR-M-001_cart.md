> **[일부 폐기]** 2026-10-23 첫 번째 각주의 "선택된 상품의 `product_id` 목록만 다음 화면([SCR-M-002_order-sheet.md](SCR-M-002_order-sheet.md))에 전달" 방식은 폐지됐다 — "2026-10-26 현행화" 각주의 [선택상품 주문하기] 동작(임시주문 생성 후 `order_sheet_id` 전달)이 현행이다. 두 각주가 충돌하면 "2026-10-26 현행화"를 우선한다.
>
> **(2026-10-23 실제 구현 반영)**: 상품 카드(위 와이어프레임엔 없음)에 상품별 체크박스가 추가됐다 — 장바구니 페이지 전체(`CartClient.tsx`)가 선택 상태(`Set<cart_item_id>`)를 들고, 기본값은 "품절이 아닌(`status === 'ON_SALE'`) 상품 전체 선택"이다(품절 상품은 체크박스 자체가 `disabled` 고정이며 선택에서 제외됨). 고객이 일부 상품의 체크를 해제하면 CTA(CartBottomBar) 금액이 선택 상품 합계(`Σ(price_sale×quantity)`, 장바구니 조건부 할인은 미반영)로 즉시 재계산되고, "선택상품 주문하기" 클릭 시 선택된 상품의 `product_id` 목록만 다음 화면([SCR-M-002_order-sheet.md](SCR-M-002_order-sheet.md))에 전달된다. 선택 0건이면 CTA 버튼이 비활성화된다. 근거: `.agents/tasks/mobile-order-ux-gaps/design.md` 결정 2.
>
> **(2026-10-23, `mobile-cart-total-reconcile` 작업 반영)** `CartSummary`("금액 요약 (예상)" 박스)도 이제 `CartBottomBar`와 동일하게 선택 상태를 반영해 재계산된다 — `CartClient.tsx`의 `buildSelectedSummary()`가 선택된 item만으로 상품금액/상품할인/주문금액(예상)을 다시 계산해 양쪽에 같은 값을 내려주므로, 두 금액 표시가 서로 다른 숫자를 보이던 기존 동작은 더 이상 발생하지 않는다. 와이어프레임은 상품 카드(정상가 취소선 + 판매가)와 합계가 일치하도록 **상품금액 = 정상가 합계**(526,000원) 기준 설계 예시(상품금액 526,000원 − 상품 할인 57,000원 − 장바구니 할인 3,000원 = 주문금액(예상) 466,000원)다. 구현은 Mock `summary`를 선택 상태와 무관하게 쓰던 방식에서 바뀌어, Mock 상품 3건을 모두 선택한 기준으로 "상품금액 566,000원 / 상품 할인 -97,000원 / 주문금액(예상) 469,000원"(Mock 상품 구성이 와이어프레임 예시와 달라 숫자가 다름)이 되고, CTA도 동일하게 469,000원으로 표시돼 두 수치가 일치한다. "장바구니 할인" 행은 조건부 할인(`cart_promotions[]`)을 선택 합계에 반영하지 않기로 결정해(`mobile-cart-total-reconcile/design.md` 결정 3) 값이 항상 0이 되므로, 실제 화면에는 이 행 자체가 나타나지 않는다 — 버그가 아니라 의도된 결과다. 근거: `mobile-cart-total-reconcile/design.md` 결정 1·3.
>
> **(`mobile-cart-back-and-quantity` 작업 반영)** 헤더 좌측에 뒤로가기 버튼(`CartBackButton`, `router.back()`)이 추가됐다. 상품 카드의 수량 +/- 버튼이 실제로 `PATCH .../cart/items/{cartItemId}/quantity`를 호출해 해당 item의 수량만 갱신한다(1~99 범위·재고초과는 버튼 비활성화로 선제 차단, 경계 밖 요청은 서버가 400/409로 방어). 품절 상품은 +/- 버튼도 비활성화된다. 근거: `.agents/tasks/mobile-cart-back-and-quantity/design.md` 과업1/과업2.

> **(2026-10-26 현행화 — 장바구니 현재 구현 요약)** 와이어프레임·이전 각주 중 현재 화면과 다른 부분을 정리한다.
> - **구현된 것**: 헤더(뒤로가기 + "장바구니 N"), 판매자별 상품 그룹, 상품 체크박스(품절 `disabled`), 수량 +/-(PATCH 연동), 삭제(DELETE 연동 후 로컬 목록 갱신 + "삭제되었습니다." alert), 품절 배지·음영, 혜택 안내 문구, 선택 기준 금액 요약(`CartSummary`), 하단 CTA.
> - **저장 방식(Mock)**: 조회·삭제는 Mock, 수량 변경은 Mock 재검증만 한다 — 삭제·수량 변경이 영속되지 않아 새로고침 시 원래 목록으로 복원된다(`CartService.kt`). "삭제 후 목록 갱신"은 화면 로컬 상태 갱신이다.
> - **미구현(프로토타입 범위 밖)**: [옵션변경] 버튼·레이어 팝업, "사용 가능 쿠폰 N장" 클릭 팝업(쿠폰 목록 팝업은 없고 혜택 안내는 텍스트 한 줄), "장바구니 할인 행사"(`cart_promotions[]`) 영역. 와이어프레임의 해당 부분은 설계안이다.
> - **혜택 안내 문구**: `💡 {coupon_benefit_text} · 포인트 잔액 {point_balance}P` + "쿠폰·포인트는 주문서에서 적용할 수 있습니다."
> - **[선택상품 주문하기] 동작 변경**: 선택된 ON_SALE 상품(`vendorId`/`productId`/`skuId`(=productId)/`productName`/`priceOriginal`/`priceSale`/`quantity`/`color`/`size`)을 요청 바디 `items`로 `POST /api/mobile/v1/my/orders/sheet`에 보내 서버에 **임시주문(TEMP)** 을 만들고, 응답의 `order_sheet_id`로 `/orders/new?sheet={order_sheet_id}`에 이동한다(실패 시 alert). 2026-10-23 각주의 "선택된 상품의 `product_id` 목록만 다음 화면에 전달(sessionStorage)" 방식은 폐지됐다. 근거: `CartClient.tsx.handleOrder()`, DL §5.

| 금액 요약 (CartSummary) | 선택된 상품 기준 재계산값(`CartClient.buildSelectedSummary`, Mock `summary`는 더 이상 그대로 쓰지 않음) | 상품금액, 상품할인, 장바구니할인, 배송비, 주문금액(예상)(= 상품금액 − 할인금액 + 배송비. 장바구니 단계에는 포인트가 없어 결제금액이 아니라 주문금액으로 표기, 2026-10-29) |
| 수량 변경 | PATCH /api/mobile/v1/my/cart/items/{cartItemId}/quantity | +/- 버튼 클릭 시 재계산 (Mock 재검증만, 영속되지 않아 새로고침 시 복원) |
| 옵션 변경 | PUT /api/mobile/v1/my/cart/items/{cartItemId}/option (API-005) | **프로토타입 미구현**(설계안). [옵션변경] 클릭 → 레이어 팝업(색상/사이즈 선택) → 변경 완료 시 재계산. 품절 판정 = 실재고 − 장바구니 선점수량 ≤ 0 (본인+타 고객 장바구니 포함), 품절 옵션 선택 불가 |
| 삭제 | DELETE /api/mobile/v1/my/cart/items/{cartItemId} | (Mock 기반 — 서버에 영속되지 않아 새로고침 시 복원) 삭제 버튼 → 성공 시 목록·선택·건수 갱신 + "삭제되었습니다." alert, 실패 시 오류 메시지 alert |

> **금액 용어 (2026-10-29 확정: 정책서 기준)**: 장바구니는 정책서 order.md 3.7.4 용어를 그대로 쓰고 "예상"만 덧붙인다 — 상품금액 → 할인금액 → 배송비 → **주문금액(예상)**. 포인트·결제금액은 주문서에서 정해지므로 장바구니에 표시하지 않는다. 화면 제목은 "금액 요약 (예상)", 합계 행은 "주문금액(예상)"이다. 옛 표기 "주문 예상 금액"·"예상 주문금액"은 폐기.
