## 7. mobile — 마이페이지 (MyPage)

### 메타블록

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-M-005 |
| 앱 | mobile |
| 접근 권한 | 로그인 회원 |
| 관련 세부UC | 해당 없음 (진입점 화면 — 하위 화면에서 UC 정의) |
| 호출 API | 설계(DQ SCR-M-005): [[DL-인터페이스명세/order|API-014, API-016]] (모두 order 도메인) · 프로토타입 실제 호출: `GET /api/mobile/v1/my/summary`(member Mock, DL 미정의) |

> **구현 현황 (2026-10-29)**: 프로토타입 마이페이지는 `GET /my/summary`(member Mock) 한 건만 호출하며 DQ에 적힌 API-014·016은 호출하지 않는다. 주문/배송 현황(`OrderStatusBar`)은 4단계(결제완료~배송완료)로 구현돼 있고, 와이어프레임의 "입금대기" 단계, 클레임 접수 현황(`ClaimStatusBar`), 미결제 건수 뱃지는 설계안이며 프로토타입 미구현이다(Mock에 `claimStatusSummary` 없음). [결제수단 관리]는 메뉴 링크(`/my/payment-methods`)만 있고 화면(라우트)이 없다. 근거: `app/my/page.tsx`, `OrderStatusBar.tsx`, `MyMenuList.tsx`.

### 화면 구성

| 영역 | 데이터 소스 (API) | 표시 내용 |
|---|---|---|
| Header | — | 로고 + 검색/장바구니/MY |
| 회원 프로필 (MyPageHeader) | GET /api/v1/members/me/summary (구버전 표기 — 현행 구현 경로는 `GET /api/mobile/v1/my/summary`, DL에 정의 없음) | 프로필 아이콘, 이름(마스킹), 등급명 |
| 포인트·쿠폰·리뷰 카드 | 동일 API → `point`, `couponCount`, `reviewCount` | 3칸 그리드: 포인트 잔액, 쿠폰 수, 리뷰 수 |
| 주문/배송 현황 (OrderStatusBar) | 동일 API → `orderStatusSummary` | 입금대기→결제완료→준비중→배송중→배송완료 5단계 카운트 + "전체보기" 링크 (**설계안** — 가상계좌 입금대기 주문을 마이페이지에서 바로 보고 취소할 수 있도록 입금대기 단계를 추가하는 안이며, 현재 구현은 입금대기 제외 4단계) |
| 클레임 접수 현황 (ClaimStatusBar) | 동일 API → `claimStatusSummary` | **프로토타입 미구현** — 접수·처리중·완료 건수 + "전체보기" 링크 → /my/claims |
| 메뉴 리스트 (MyMenuList) | — (정적) | 주문결제(주문/배송조회, 취소/반품/교환, 결제수단), 혜택(쿠폰함, 포인트), 활동(리뷰, 문의), 설정(배송지, 회원정보, 로그아웃) |
| BottomNav | — | 홈/기획전/검색/MY |
