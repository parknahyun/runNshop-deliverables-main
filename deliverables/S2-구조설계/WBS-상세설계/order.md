# WBS (계획·실적 통합) — Order 도메인 (Bolt 기준: Bolt1~Bolt16)

> **단계**: 구조설계 (S2) Task 산출물, Scope: Domain→Bolt
> **문서종류**: Task (계획+실적을 같은 표에 유지하는 living document — 작업 끝날 때마다 갱신)
>
> **작성 목적**: 주문·결제 작업을 **16개 Bolt**(아래 §0 매트릭스의 열, 작업순 — 사용자 정의 12열 중 결제(구 Bolt5)·클레임 결제(구 Bolt8) 열을 업무 시나리오 기준 하위 Bolt로 나누고 순차 번호를 매김)로 관리한다. 행은 **대상 화면 × 주요 기능**, 열은 **Bolt**이며, Bolt 하나는 한 열의 모든 셀(여러 화면·기능을 가로지르는 흐름 단위)이다. 예: **Bolt1 주문 신청 = 장바구니 → 주문서 → 주문완료·목록·상세의 기본 흐름 1개 Bolt**. 계획(작업 항목 수·시간)과 실적(상태·완료일·6·7 반복 횟수·근거)을 Bolt 단위로 한 표에서 관리하고, Bolt 안의 세부 작업은 §2 작업 항목으로 추적한다. 이전 기능·상태전이 기준 Bolt(#0~#22)는 부록 A, 시나리오 기준 구성은 부록 B에 보존한다.
>
> **Bolt 작업 절차(9단계)**: 1 설계 패키지 작성(AI) → 2 설계 확인(휴먼, 가벼운 게이트) → 3 설계 확인(AI, 구현 전 갭 점검) → 4 구현 → 5 AI 점검 → 6·7 휴먼 소스확인+기능점검(동시, 지적 없을 때까지 반복) → 8 현행화 → 9 현행화 검토(휴먼). 휴먼 게이트는 2·6·7·9.
> **결제 확장 원칙**: 새 PG·결제수단은 Payment 모듈(어댑터) 추가만으로 확장하고 Order·Claim은 영향받지 않는다(상세: [payment.md](payment.md) 머리말).
> **데이터 구현 원칙(Bolt1~, 2026-10-29)**: 주문·결제(Order·Payment) 모듈은 **DB 기준**으로 구현한다(Mock 서버 응답 금지). 타 도메인(Catalog·Promotion·Member·Vendor 등)은 **Port + Mock이 기본**이며, 이미 DB 샘플 작업이 되어 있으면 그대로 유지한다(예: Catalog 재고 `cat_sku_stock`). 따라서 장바구니(Order 소유)는 Bolt1에서 DB 저장으로 전환하고(SC01-3), 쿠폰·포인트 값(Promotion·Member)과 배송지(Member)는 Mock을 유지한다.
> **산정 모델**: 단계별 최소 시간 AI 0.5h·휴먼 1.0h, 6·7은 같이 진행해도 휴먼 2단계(회당 2h), 반복·AI 보정 최소 2회. **Bolt 통합 산정**: 휴먼 = 6h + 3h × (작업 항목 수 − 1) (항목이 늘 때 설계 확인·소스확인·검토를 함께 하므로 항목당 3h만 가산), 연동 성격 Bolt(Bolt4·5·6·7·9·10·11·12·16)는 ×1.25 올림. AI = 작업 항목별 AI 시간의 합. 가정은 실적(6·7 반복 횟수)으로 보정한다. 수식은 워크시트 `weekly-report/tmp/주문화면_기능목록_작업순서.xlsx`('산정모델'·'Bolt1-16'·'Bolt목록').

## 4. 갱신 규칙

1. 새 작업이 끝나면 `deliverables/S4-구현/YYYY-MM-DD-주요작업.md`를 작성한 뒤, §2에서 해당 **작업 항목 행**의 상태·완료일·구현 내용·근거를 갱신하고 §1 해당 Bolt의 상태를 맞춘다(Bolt 9단계 중 8 현행화 시점).
2. 휴먼 게이트(6·7 소스확인+기능점검, 9 현행화 검토)를 마치면 §1의 `구현 완료 · 휴먼 확인 대기`를 `완료`로 바꾸고 **6·7 반복 횟수**를 기록한다.
3. 새 작업이 기존 Bolt에 안 맞으면 §0 매트릭스에서 위치(행·열)를 정하고 §2에 항목을 추가한다. Bolt 자체를 늘릴 때는 매트릭스 열을 추가한다(DQ §7-3·워크시트와 함께 갱신).
4. "미착수"는 비워두지 않고 반드시 `미착수`로 명시한다. 계획 시간은 워크시트 '산정모델'에서 재계산해 반영한다.
5. 의존성 맵·일정(날짜)·담당자 배정은 아직 수립 전이다. 연동 성격 Bolt는 상대 모듈 설계 확정(착수 조건) 이후에 착수한다.
