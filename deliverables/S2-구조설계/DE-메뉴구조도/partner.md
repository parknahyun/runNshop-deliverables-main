## Catalog 화면 ↔ API 매핑 (2026-09-28 보강)

> DN-화면레이아웃/catalog-partner.md에서 설계된 5개 화면을 메뉴 경로에 연결한다.

| 메뉴 경로 | 화면 (SCR-ID) | 주요 호출 API (DL §) |
|---|---|---|
| 상품관리 › 상품등록 | 상품 등록 (SCR-P-C01) | §1 임시저장, §2 심사요청 |
| 상품관리 › 상품등록 › (반려 상품) | 반려 상품 재작성 (SCR-P-C02) | §29 상세조회(rejectReason 포함), §7 재제출 |
| 상품관리 › 상품목록 | 상품 목록 (SCR-P-C03) | §28 상품 목록 |
| 상품관리 › 상품목록 › (행 클릭) | 상품 상세·수정 (SCR-P-C04) | §29 상세조회, §8~11 기본정보/이미지/옵션/단종, §16·§16-1 가격 |
| 상품관리 › 상품목록 (행 액션) | "복제" 버튼 (SCR-P-C03 내, 별도 메뉴 아님) | §33 상품 복제 등록 |
| 상품관리 › 대량등록 | 상품 대량등록 (SCR-P-C06, 2026-11-09 소급 반영) | §34 상품 대량등록 |
| 상품관리 › 상품목록 › (행 클릭) › 기본정보 탭 (필드 추가) | 상품 상세·수정 (SCR-P-C04) | §8 기본정보 수정(maxOrderQuantity 필드, 2026-11-09 소급 반영) |
| 상품관리 › 재고관리 | 재고 관리 (SCR-P-C05) | §13-1 SKU 통합조회, §13 재고 수량 변경 |

> **구 메뉴구조와의 차이**: 기존 "상품목록" 1개 2depth에 등록·목록·수정을 모두 뭉쳐뒀던
> placeholder를 DN 설계에 맞춰 "상품목록"과 "상품등록" 2개로 분리했다 — 등록 흐름(초안
> 작성→심사요청→반려재작성)과 목록·조회·수정 흐름이 화면상 별개 경로이기 때문(DK
> §2·§4 vs §5).

> **2026-11-09 소급 반영**: REQ-CAT-056·057·059b(복제등록·대량등록·주문수량제한)가
> 2026-11-06 DBA/DD 신설 당시 DK·DL에만 반영되고 메뉴구조도에는 등재되지 않았던 공백을
> 메웠다. "대량등록"은 신규 2depth 메뉴로, "복제"는 상품목록 화면 내 행 액션으로,
> 최대 주문수량은 상품상세·수정 화면의 기본정보 탭 내 입력 필드로 추가했다(별도 메뉴
> 불필요). SNS 공유는 고객(mobile) 전용 기능이라 partner 메뉴에 영향이 없다.
